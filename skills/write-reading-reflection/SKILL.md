# 读书心得生成器

基于一本书的划线与想法（划线 + 想法）和用户口述的个人感悟，撰写一篇中文读书心得，保存到 `reflections/<书名>/读书心得.md`。格式与语言风格必须严格对齐用户过往的读书心得。

## 工作流程

### 第一步：确认书籍与来源

- 确认书名、作者。
- 判断书籍来源：
  - **微信读书**：调用 weread-skills（微信读书助手 skill）搜索书籍并导出划线与想法到 `notes/<书名>/划线与想法.md`，遵循 AGENTS.md 约定（每本书一个目录、中文 Markdown、单条划线/想法不附日期）。
  - **纸质书**：请用户提供自己整理的划线与想法文件（如 `notes/<书名>/划线与想法.md`）。若文件格式与下方"划线与想法标准格式"不一致（缺少头部信息、没有 `>` 引用标记），先将其整理为标准格式，再开始写作。
- 若书在微信读书上阅读，`reflections/` 下的目录名必须与 `notes/` 下同名书一致（例如 `notes/睡眠革命：新版/` 对应 `reflections/睡眠革命：新版/`）。

### 第二步：收集个人口述感悟

主动向用户提问，完整记录口述内容，作为「三、心得体会」的核心素材。建议问题：

- 读这本书的背景与心境（什么时候读的？当时处于什么状态？）
- 最触动、最有共鸣的内容是什么？为什么？
- 书中观点如何与自己的经历（工作、学习、生活）产生联系？
- 读完后自己的认知或行为发生了什么改变？
- 对这本书的整体评价如何？

口述内容只是写作素材，**不要原话照搬用户的口头表达**：写作时应根据上下文自行整理、提炼和润色，使语言书面化、条理清晰，同时保留其中的真实经历与观点。

口述感悟同时也是「二、内容分享」**筛选摘录**和**撰写解读**的依据：用户提到的触动点、共鸣点，对应的划线应优先入选，并在解读中体现用户的理解与收获。

### 第三步：学习用户写作风格

动笔前，阅读 `reflections/` 下至少 2-3 篇过往读书心得作为风格参照（优先读 `reflections/被讨厌的勇气/读书心得.md`、`reflections/富爸爸穷爸爸/读书心得.md`、`reflections/纳瓦尔宝典/读书心得.md`），模仿其结构与文风。

### 第四步：精选摘录（内容分享）

「二、内容分享」**不是划线与想法的搬运**，不要把 `划线与想法.md` 中的全部内容照搬进心得。先通读全部划线与想法，再按以下规则精选：

1. **只摘精华**：只保留最精华、最重要、最触动用户的段落。是否"触动用户"以第二步的口述感悟为准——用户提到的观点、共鸣点、相关经历所对应的划线优先入选；用户写过 `**想法**` 的划线也说明其有共鸣，可优先考虑。
2. **意思不重复**：多条划线表达相同或相近意思时，只保留表述最完整、最有力的一条，其余舍弃。
3. **适度精简**：摘录数量以支撑观点为度，一般全书约 10-25 条（视划线总量和书的篇幅调整），宁缺毋滥；与口述感悟和本书核心观点都无关的划线可以不选。
4. **组织小节**：可以按原书章节拆分子小节，也可以根据内容主题重新归类，将讲同一件事的划线（即使来自不同章节）合并到同一子小节中；小节标题需提炼主题，不必沿用原章节名。
5. **合并引用块**：原文中互相邻近、属于同一话题的段落，放进同一个 `>` 引用块中（段落之间用单独的 `>` 行分隔，参考《被讨厌的勇气》读书心得的样式）；不同话题的引用分成不同的引用块，中间穿插解读。
6. **配上解读**：每个引用块之后，根据用户口述的感悟，写出用户对这些句子的理解、感想或收获（结合用户的真实经历），而不是复述原文；不得编造用户未提及的具体经历。
7. **逐字准确**：入选的句子必须逐字照录原文，不改写、不拼接成原文没有的句子；可以只摘录一段划线中的完整句子，但不改变原意。
8. **素材不足先追问**：选定摘录后、动笔之前，逐一检查每个引用块是否有足够的口述素材支撑解读。若某些摘录无法确定用户的感受或对应的现实经历，**先向用户提问，不要凭空补写**：
   - 列出这些摘录（附原文或其要点），针对每条提出具体、引导性的问题，例如："读到这句时你有什么感受？""工作或生活中有没有类似的经历？""这句话让你改变了什么想法或做法？"
   - 问题要具体、便于回答，可一次性汇总提问，避免多轮零散追问；
   - 用户的回答同样作为写作素材，整理润色后写入解读，不原话照搬；
   - 用户可以选择对某些摘录**不作解释、只保留摘录**：此时照常保留该引用块，后面不配解读（可与相邻引用块合并，或仅用一句引入语衔接上下文），不要自行补写感想；
   - 若用户表示没有特别感受，也可将该摘录舍弃。

### 第五步：撰写读书心得

按下方「输出格式」与「写作风格要求」撰写，保存到 `reflections/<书名>/读书心得.md`。

### 第六步：自检

- [ ] 标题为 `# 《书名》读书笔记｜副标题`
- [ ] 「一、关于本书」为封面图 + 简介
- [ ] 「二、内容分享」中所有原文引用均来自划线与想法文件，逐字准确，不编造
- [ ] 「二、内容分享」只摘录了精华划线，没有照搬全部划线，入选划线之间意思不重复，且覆盖了用户口述中提到的触动点
- [ ] 邻近且同话题的划线已合并在同一个 `>` 引用块中，每个引用块后都有结合用户感悟的解读（用户明确选择"只摘录、不解释"的除外）
- [ ] 解读中提到的感受与经历均来自用户口述或追问后的回答，没有编造
- [ ] 「三、心得体会」融入了用户口述的真实经历与感悟，且已整理润色、未原话照搬
- [ ] 文末已附生成声明（`---` + 引用行），skill 名称链接到 GitHub 仓库中该 skill 的位置
- [ ] 文风与过往心得一致：第一人称、结合个人经历、真诚有思考

## 输出格式

```markdown
# 《书名》读书笔记｜副标题

## 一、关于本书

<img src="./cover.jpg" width="120" alt="book cover">

简介：……（2-4 句概括本书内容与主题，可带一句本书对自己的意义）

## 二、内容分享

### 2.1 小节标题

引入段落（1-2 句引出本节主题）。

> “原文引用一（单独一个话题）”

围绕引用一的个人解读（结合口述感悟与自身经历）……

> “原文引用二（与引用三相邻、同一话题，合并在同一引用块）”
>
> “原文引用三”

围绕引用二、三的个人解读……

### 2.2 小节标题

……

## 三、心得体会

第一人称回顾阅读背景与心境，结合个人经历谈收获与改变（可用"曾经的我……现在的我……"结构），最后总结对本书的评价。

---

> 本文由 Claude Code 调用 [write-reading-reflection](https://github.com/cedar-ai-project/personal-librarian/tree/main/skills/write-reading-reflection) skill 自动生成。
```

格式说明：

- 封面图：若 `reflections/<书名>/cover.jpg` 存在则保留 `<img>` 行；封面图由用户从豆瓣读书等网站下载提供，生成时若缺失则省略该行并提醒用户补充。
- 连续多条引用之间用单独的 `>` 行分隔（避免 markdownlint MD028）。
- 「二、内容分享」小节数量视书籍内容而定，一般 3-7 节；也可采用 `**Insight N：小标题**` 的加粗提纲式分节（参考《新收入》《纳瓦尔宝典》的心得）。
- 文末必须附上生成声明：`---` 分隔线后跟一行引用，注明本文由 Claude Code 调用本 skill 自动生成，skill 名称链接到 GitHub 仓库中该 skill 的位置（https://github.com/cedar-ai-project/personal-librarian/tree/main/skills/write-reading-reflection）。

## 写作风格要求

（基于用户过往读书心得总结，写作时必须遵守）

1. **副标题**：短小精悍，点出本书核心价值，如"接纳自我，勇敢地感受生活"、"找寻自我之路"、"财商教育启蒙之作"。
2. **简介**：客观介绍 + 个人视角，2-4 句，不用广告式书评腔。
3. **内容分享**：每节 = 引入 + 原文引用（blockquote）+ 个人解读，引用后紧跟解读，不要只堆引用不解释（用户明确选择"只摘录、不解释"的摘录除外）。关键概念用 **加粗** 标出（如 **"身心分离模式"**）。摘录须经过精选，规则见「第四步：精选摘录」。
4. **引用**：必须来自划线与想法文件，逐字引用；只选精华、不重复，邻近且同话题的多条引用合并在同一个 `>` 引用块中，但不要改变原文。
5. **个人解读**：第一人称，结合自己的真实经历（程序员、职场新人、大厂工作、焦虑内耗、早起习惯、理财观念等），口语化但有思考深度；可以坦诚写自己的不足与改变。
6. **心得体会**：写阅读本书时的背景与心境（"初读本书时，正值……"），曾经的自己与现在的自己对比，落到具体改变与行动，最后给出整体评价。口述感悟不要原话照搬，需自行整理润色为书面语言：保留真实经历与观点，去除口语中的冗余、碎片和重复。
7. **语言**：中文，第一人称，真诚、克制、有深度，不堆砌形容词与空话；篇幅参考过往心得（约 1500-4000 字）。
8. **格式规范**：遵循 AGENTS.md（每本书一个目录、中文 Markdown、单条划线与想法不附日期）；文末附上 skill 生成声明（见「输出格式」）。

## 划线与想法标准格式

整理手打文件或核对导出文件时使用：

```markdown
# 《书名》划线与想法

- 作者：xxx
- 导出日期：YYYY-MM-DD
- 来源：[打开阅读](链接)   ← 仅微信读书导出的文件包含此行
- 划线数：N，想法数：M

## 章节名

> 划线内容一

> **想法**：想法内容

> 划线内容二
```

- 每条划线单独一段 blockquote，同一章节内相邻划线以单独的 `>` 行分隔，章节最后一条划线后直接接空行；
- 想法（点评）紧跟在对应划线之后，格式为 `> **想法**：内容`；
- 单条划线/想法不附日期（AGENTS.md 规则）。
