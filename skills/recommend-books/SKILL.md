# 好书推荐

在 personal-librarian 仓库根目录下工作。每次推荐是一「期」，保存为 `recommendations/<YYYY-MM>.md`（同月再出一期时用 `<YYYY-MM>-2.md`），往期保留不动。网站「好书推荐」页面（`site/`）展示最新一期，并可切换查看往期。

本 skill 的脚本都在 `<本 skill 目录>/scripts/` 下，需要 `WEREAD_API_KEY` 环境变量（未设置时提示用户 `export WEREAD_API_KEY=<你的apikey>`）：

| 脚本 | 用途 |
| ---- | ---- |
| `lookup_book.py <书名>...` | 搜索微信读书，返回 bookId、评分、评分人数、评分标签、封面、链接 |
| `lookup_book.py --id <bookId>` | 查看单本书的完整信息（含简介、分类） |
| `fetch_shelf_status.py --unread` | 列出书架上没读完、且不在仓库里的书（「书架上的遗珠」候选） |
| `fetch_shelf_status.py` | 刷新 `recommendations/shelf-status.json`：每本推荐过的书是否在书架上、是否读完 |

## 工作流程

### 第一步：了解近期需求（必需）

先问用户，再动手选书：

- 近期想读什么方向？（例如继续学投资、想读点轻松的小说、补技术书）
- 有没有不想要的？（例如不想读太厚的书、某个领域暂时不感兴趣）

### 第二步：了解用户

- `profile/阅读画像.md`：阅读人格、关键词、核心关注主题。
- `profile/reading-stats.json`：偏好分类、读得最久的书。
- `reflections/*/读书心得.md` 与 `notes/*/划线与想法.md`：用户的真实想法，是写推荐理由的依据。
- `notes/*/阅读推荐.md`：书中推荐或提到的书。
- `recommendations/*.md`：往期推荐过的书（不得重复推荐）。

### 第三步：收集候选

- AI 根据画像与近期需求提出候选，同时参考：
  - `fetch_shelf_status.py --unread` 的书架未读书；
  - 微信读书 `/book/recommend`（为你推荐）与 `/book/similar`（用户最喜欢的书的相似推荐）；
  - 用户读过的书里推荐或提到的书。
- 用 `lookup_book.py` 逐本核实，选定版本时优先评分高、评分人数多的版本。

### 第四步：筛选与分组

一期 10–15 本，按推荐动机分为以下四组（某组没有合适的书可以省略）：

| 分组 | 选书标准 |
| ---- | ---- |
| 延续你的兴趣 | 在用户已有的关注主题和近期需求上读得更深 |
| 拓展视野 | 用户很少读的领域（历史、科学、哲学、文学经典等），最好能与已有兴趣建立联系 |
| 书架上的遗珠 | 用户已加入微信读书书架、但还没读完的高分书 |
| 书中提到的书 | 用户读过的书里推荐或引用的书 |

**排除规则**：

- `notes/`、`reflections/` 中已有的书；
- 往期已经推荐过的书；
- 低分书：微信读书评分低于 80%，或评分人数少于 300；
- 快餐式成功学（如「X 天学会……」「……避坑指南」「一本书读懂《……》」类解读书）。

### 第五步：撰写

- **一句话简介**：自己概括这本书讲什么，不超过 50 字，不照抄营销文案。
- **推荐理由**：2–3 句，必须关联用户读过的书或用户自己的想法，说明「为什么现在推荐给你」；凡涉及用户的经历、观点、书架状态，都要能在素材或 API 数据中找到依据，不编造。
- **关联**：推荐理由中提到的已读书，写作 `《书名》`，书名必须与 `notes/`、`reflections/` 下的目录名一致。

### 第六步：与用户确认（必需）

先把书单草稿（分组、书名、评分、一句话理由）展示给用户，用户可以删除、替换或调整。确认后再写入 `recommendations/<YYYY-MM>.md`。

### 第七步：刷新书架状态

写入后运行 `fetch_shelf_status.py`，刷新 `recommendations/shelf-status.json`。用户以后读了推荐的书，网站会据此（以及 `notes/`、`reflections/` 中是否出现这本书）显示「已在书架」「在读」「已读」。

### 第八步：自检

- [ ] 10–15 本，无重复，不含排除规则中的书
- [ ] 每本书都经 `lookup_book.py` 核实，bookId、评分、封面、链接来自接口
- [ ] 推荐理由关联了用户读过的书或想法，且有依据
- [ ] 格式与「输出格式」完全一致（网站据此解析）
- [ ] `recommendations/shelf-status.json` 已刷新
- [ ] 文末已附生成声明

## 输出格式

`recommendations/<YYYY-MM>.md` 必须严格使用以下结构：

```markdown
# 好书推荐 · YYYY 年 M 月

> 推荐日期：YYYY-MM-DD

<本期推荐语：2–3 句，说明本期的主线和用户近期的需求>

## 延续你的兴趣

### 《<微信读书上的完整书名>》

- 作者：<作者>
- bookId：<bookId>
- 评分：<评分>%（<评分标签>，<评分人数> 人评分）
- 封面：<封面 URL>
- 链接：<微信读书链接>
- 关联：《已读书名》《已读书名》

简介：<一句话简介>

推荐理由：<2–3 句推荐理由>

## 拓展视野

## 书架上的遗珠

## 书中提到的书

---

> 本文由 Claude Code 调用 [recommend-books](https://github.com/cedar-ai-project/personal-librarian/tree/main/skills/recommend-books) skill 自动生成。
```

格式要点：

- 分组标题固定为上表中的四个名称，按表中顺序排列。
- 字段使用全角冒号「：」；没有评分标签时写 `<评分>%（<评分人数> 人评分）`；没有关联书时省略「关联」行。
- 遵循 AGENTS.md：中文 Markdown。
