# 知识树生成器

在 personal-librarian 仓库根目录下工作，产出 `knowledge/知识树.md`，供网站「知识树」页面（`site/`）以自下而上的树形展示：根「我」→ 领域 → 子领域 → 书 → 知识点。

## 工作流程

### 第一步：判断是首次生成还是增量更新

- 列出 `notes/`、`reflections/` 下的全部书（目录名即书名），与 `knowledge/知识树.md` 中已有的 `#### 《书名》` 对比。
- **首次生成**（文件不存在）：设计完整的分类结构，为每本书提取知识点。
- **增量更新**（文件已存在）：**保留用户已确认的领域、子领域和已有书的知识点不动**，只为新书归类、提取知识点；移除已不在仓库中的书。只有用户明确要求时，才调整已有结构。

### 第二步：设计分类（首次生成，或新书放不进已有分类时）

- 按知识领域自定义分类，贴合用户的阅读视角，不照搬微信读书或图书馆分类。参考 `profile/阅读画像.md` 中的核心关注主题。
- 领域 5–8 个，每个领域 1–3 个子领域；名称简短（2–6 字）。
- 小说、文学作品可以单独成为一个领域。

### 第三步：提取知识点

每本书 2–5 个知识点：

- **名称**：2–10 字的概念或观点（如「资产与负债」「以教代学」）。
- **一句话解释**：不超过 50 字，取自用户的划线、`**想法**：` 段落或读书心得中用户自己的表述；不编造书中没有的内容。
- **出处**：知识点所在的章节，写作 `读书心得 · <小节标题>` 或 `划线与想法 · <章节标题>`。标题必须与对应文件中的 `##`/`###` 标题文字**完全一致**（网站据此生成跳转到笔记原文的链接）；有读书心得的书优先引用心得。
- **跨书关联**：不同书讲的是同一个概念时，使用**完全相同的名称**（如《费曼学习法》《认知觉醒》《海绵阅读法》中的「输出式学习」），网站会把它们关联高亮。只在确有依据时才统一名称。

### 第四步：与用户确认（必需）

先展示草稿：分类结构（领域 → 子领域 → 书）和每本书的知识点名称；增量更新时只展示新增和变动的部分。用户确认或修改后再写入 `knowledge/知识树.md`。

### 第五步：自检

- [ ] 仓库中的每本书都恰好出现一次
- [ ] 格式与「输出格式」完全一致
- [ ] 运行 `cd site && npm run data`，没有 `knowledge:` 开头的警告（书名或出处对不上时会提示）
- [ ] 文末已附生成声明

## 输出格式

```markdown
# 我的知识树

> 更新日期：YYYY-MM-DD

## <领域>

### <子领域>

#### 《<书名，与 notes/ 或 reflections/ 下的目录名一致>》

- <知识点名称>：<一句话解释>（出处：读书心得 · <小节标题>）
- <知识点名称>：<一句话解释>（出处：划线与想法 · <章节标题>）

---

> 本文由 Claude Code 调用 [build-knowledge-tree](https://github.com/cedar-ai-project/personal-librarian/tree/main/skills/build-knowledge-tree) skill 自动生成。
```

格式要点：

- 领域、子领域、书分别使用 `##`、`###`、`####` 标题，按希望在树上从左到右的顺序排列（相近的领域放在一起）。
- 知识点名称与解释之间用全角冒号「：」；出处放在行末的全角括号中，「出处：」后接文档名、` · `、标题。
- 遵循 AGENTS.md：中文 Markdown。
